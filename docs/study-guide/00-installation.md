## 本篇的核心问题

安装篇解决的是“同一份代码到底由哪个 Python、哪些库、哪种计算设备执行”。其长期有效的内容是环境隔离和执行链路，而不是逐字复制当年固定的安装命令。本仓库已有独立学习环境和服务管理脚本，日常学习应沿用该部署，不需要为跟随原书而降级环境。

## 按原文三部分梳理

| 原文部分 | 重点解析 | 在当前仓库中的对应物 |
| --- | --- | --- |
| Installing Miniconda | 隔离环境让不同项目拥有各自的解释器和依赖，激活环境只是改变当前终端的查找路径。 | 本部署使用项目内 `.venv/`；创建方式虽与原书 Conda 不同，隔离目标一致。 |

## 四层执行链路

浏览器把执行请求发送给 Jupyter Server，服务器把请求交给 Notebook 内核，内核中的 Python 再导入 PyTorch 与 `d2l`。GPU 运算还需要框架的 CUDA 用户态运行库和服务器驱动配合。

因此，要区分以下对象：

- **Python 环境**：决定解释器、包版本和导入位置。
- **Jupyter 内核（kernel）**：执行单元格的进程；其环境不一定等于启动网页服务的环境。
- **深度学习框架（framework）**：提供张量与自动微分；能导入框架不等于 CUDA 算子一定能运行。
- **教材辅助库**：封装数据、模型、训练器和绘图逻辑；阅读时可回查 [d2l/torch.py](../../d2l/torch.py)。

原文固定的 Python 3.9、PyTorch 2.0.0 等属于该版安装示例。本次部署记录的是 Python 3.12.13、PyTorch 2.11.0+cu128 与 torchvision 0.26.0+cu128；这是已有安装和验证记录，不是要求任意机器都采用这些版本。重建当前环境时应按本项目安装脚本执行。

## 建议先观察的最小信息

以下是**供学习者执行的检查片段，本次编写导读没有新增执行实验**：

```python
import sys
import torch
from d2l import torch as d2l

print(sys.executable)
print(torch.__version__)
print(d2l.__file__)
print(torch.cuda.is_available())
```

前三项回答“用了哪个解释器、哪个框架版本、哪一份教材辅助库”；最后一项回答当前进程能否发现可用 CUDA 环境。进一步确认算子执行时，可分配一个很小的 GPU 张量并做一次运算，而不必先启动大型训练。若章节依赖额外库，应先确认该节实际使用的框架，避免把其它框架分支的依赖混入当前环境。

## 访问教材与学习代码

本部署中，已登录 Jupyter 后可通过 `http://127.0.0.1:8888/book/` 阅读教材。Notebook 入口为 `http://127.0.0.1:8888/lab/tree/notebooks/pytorch`。这些地址沿用现有的服务器访问通道；若在另一台电脑上使用，具体转发方式见部署说明。

网站构建环境 `.venv-book/` 只负责把源码转换为页面。它与 `.venv/` 学习环境分开，避免文档工具的依赖约束影响 GPU 学习环境。网页中的代码和公式可正常显示，也不等于该网页构建过程执行过训练。

## 常见问题的定位顺序

| 现象 | 优先核对 | 为什么 |
| --- | --- | --- |
| `ModuleNotFoundError` | 当前内核解释器、包安装位置、实际框架分支 | 最常见的是装包和执行处于不同环境。 |
| 导入成功但 CUDA 不可用 | 当前进程的设备可见性、框架构建、驱动与运行库 | Python 导入和 GPU 执行是不同层次。 |
| Notebook 结果与源码不一致 | 单元格执行顺序、旧变量、当前目录、本地文件版本 | Notebook 会保留进程状态；屏幕顺序不保证执行顺序。 |
| 能开 Jupyter，不能开独立教材端口 | 使用 `/book/` 同端口入口 | 浏览器连接路径与服务器端服务状态需要分开判断。 |
| 显存不足 | 批量大小、输入尺寸、模型状态与其他任务 | 不必先重装框架；应先理解实际分配的张量。 |

## 自测与回答线索

1. **在终端安装成功，Notebook 为什么仍找不到包？** 线索：核对 `sys.executable`，不要只看终端环境名称。
2. **`d2l` 与 PyTorch 各负责什么？** 线索：教材组织与辅助逻辑，对比通用张量和自动微分能力。
3. **为什么不直接照抄原文版本命令？** 线索：教材的历史测试环境、当前硬件和已部署环境并非同一对象。
